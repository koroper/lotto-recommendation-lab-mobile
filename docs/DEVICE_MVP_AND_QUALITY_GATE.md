# 실기기 MVP 완료와 추천 모델 개선 기준

## 2026-10-26 실제 삼성 휴대폰 MVP QA

사용자가 실제 삼성 휴대폰에서 다음 항목의 정상 동작을 직접 확인했다.

1. 앱 실행 및 1248회 추천 표시
2. 최신 1247회 데이터 확인
3. 연구 / 기록 / 설정 화면 동작
4. 앱을 닫았다가 재실행해도 정상 동작

**판정:** Android MVP의 *실기기 기능 QA는 완료*.

이 확인은 2026-10-26 기준이다. 이후 추첨 결과가 갱신되면 추천 대상 회차도 달라진다.

**명시적으로 보존해야 할 사실:** 기존 앱을 제거한 뒤 재설치했다. 따라서 과거 구매 확정 기록과 연구 설정이 자동 이관되었다고 주장하지 않는다. 공식 APK는 개인 휴대폰 설치용 debug 서명이며 Google Play 출시용 서명을 의미하지 않는다. 기존 \`com.lotto.lab\` 앱을 다음 버전에서 업데이트할 때는 설치본 서명과 빌드 키를 대조한다.

## 제품의 변하지 않는 우선순위

> 실제 과거 로또 데이터를 토대로 매주 구매할 만한 가장 유력한 로또 번호 **조합**을 추천한다.

단, 공정한 로또 6/45에서 각 특정 6개 조합의 실제 1등 당첨 확률은 동일한 1/8,145,060이다. 내부 순위·확신도·추천 점수는 당첨확률이나 수익 보증이 아니다.

추가 연구는 위 제품 목적에 기여해야 하며, 연구 자체를 위한 후보 탐색 확대, 임의 모델 추가나 임계값 완화가 목적이 되어서는 안 된다.

## Phase 3 Step 1 — 실제 5게임 포트폴리오의 평가 기준 (이번 작업)

기존 \`quick_research\`는 주로 **모델 상위 6개 번호의 적중 개수**를 평가한다. 이는 사용자가 실제 구입할 **복수 게임 조합 전체**의 효과와 다르므로, 연구 점수만으로 주간 추천 변경을 정당화하지 않는다.

새 \`quality/portfolio_backtest.py\`는 다음을 평가한다.

- 검증 대상 각 회차의 *이전 이력만* 입력하여 5게임을 생성한다.
- 동일한 회차·동일한 5게임 수로 **표준 / 분산 / 무작위** 포트폴리오를 비교한다.
- 주요 지표: 게임당 평균 일치 번호 수, 회차별 최다 일치 번호 수, 하나 이상 3개·4개·5개·6개 일치한 회차 수.
- 무작위 포트폴리오를 동일 조건에서 여러 번 생성해 경험적 기준 분포를 기록한다.
- 보너스 번호·당첨금액·실제 지출/수익은 이 단계의 최적화 목표가 아니다.
- 현재 모델 가중치는 6개 동일비중으로 고정한다. 연구 후보의 자동 적용을 하지 않는다.
- 모든 비교는 **기술적·기술통계적 결과만** 제공하며, 미래 추첨의 우월성을 증명한다고 주장하지 않는다.

### 로컬에서 실제 당첨 이력으로 실행

공개 원본/미러 JSON을 내려받아 \`lotto-history.json\`으로 로컬에 준비한다. 지원 포맷: \`{"data":[{"drawNo":...}]}\`, \`[{"draw_no":...}]\`, \`[{"draw":...}]\`. 스크립트가 자체적으로 네트워크에 접근하지 않는다.

\`\`\`bash
python quality/portfolio_backtest.py --history lotto-history.json \
  --window 24 --games 5 --repetitions 100 \
  --json-output portfolio-report.json
\`\`\`

이력 내 마지막 24개 실제 추첨을 대상으로 총 5게임을 **그 당시까지 공개된 이력만으로** 작성한다. 동일 원칙으로 추가 기간을 평가할 수 있지만, 특정 기간에서 좋은 결과만 골라보고하지 않는다.

JSON의 \`perDraw\` 항목으로 각 회차의 실제 일치 번호 수를 추적할 수 있다. 전체 기준과 서로 다른 기간의 결과가 엇갈리면 이를 숨기지 않는다.

### 모델 개선 제안의 승인 기준 (후속 작업)

1. 실전 구매 포트폴리오 성과가 기존 동일가중치 표준 방식보다 독립적인 **후행 평가 구간**에서 개선되어야 한다.
2. 개선 가설과 후보는 검증 대상 구간 **이전**에 고정되어야 한다. 검증 데이터를 보고 후보를 고른 뒤 동일 검증 데이터를 독립 증거로 재사용하지 않는다.
3. 같은 게임 수·기간·평가 방식으로 비교하며, 일부 운 좋은 회차만 강조하지 않는다.
4. 번호 모델·조합 모델의 기존 골든 패리티, 구매 기록·추천 ID, 연구 누출 방지 테스트가 모두 통과해야 한다.
5. 검증이 불충분하면 **HOLD = 기존 추천 유지**. 모델 가중치나 UI 추천 번호가 임의로 변경되지 않는다.
6. 실제 구매 기록을 이용한 성과와 가상 과거 시뮬레이션 결과를 절대 합치지 않는다.

이 단계는 검증 도구 구축과 안전성 확인이다. 과거 데이터 실측 결과 및 독립 보류구간 승인이 나오기 전에는 새로운 추천 모델을 배포하지 않는다.
